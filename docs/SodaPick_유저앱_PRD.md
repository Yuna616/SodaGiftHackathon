# PRD: SodaPick 유저 앱 (참가자용)

> 상위 문서: `SodaPick_기획안.md`, `SodaPick_PRD.md` (통합본)
> 이 문서의 목적: 유저 앱을 먼저 만들기로 했으므로, 실제 빌드에 쓸 수 있는 수준까지 상세화
> 기준 시나리오: 기획안에서 MVP 우선순위로 추천한 **"K팝 컴백 위클리 픽"** — 이 문서의 모든 예시는 이 캠페인을 기준으로 서술함

---

## 1. 목표 & 성공 지표

**제품 목표**: 참가자가 무료로 예측에 참여하고, 당첨 시 실제 크로스보더 리워드를 마찰 없이 받는 경험을 제공하며, 그 클레임 경험을 소다기프트 신규 발신자 전환의 진입점으로 만든다.

**성공 지표 (실 서비스 기준 — 해커톤 데모에서는 정성적 시연이 우선이지만 설계 시 아래를 염두에 둘 것)**

| 지표 | 정의 |
|---|---|
| 참여율 | 캠페인 노출 대비 예측 제출 비율 |
| 바이럴 계수 | 참가자 1인당 발생한 초대 성공(신규 가입) 건수 |
| 클레임 완료율 | 당첨자 중 실제로 선물을 수령까지 완료한 비율 |
| **발신 전환율 (북극성 지표)** | 클레임 완료자 중 "당신도 보내보세요" CTA를 클릭해 소다기프트 발신 플로우로 넘어간 비율 — 이게 이 제품이 실제로 신규 고객 유치에 기여했는지를 보여주는 핵심 숫자 |

## 2. 스코프 가드레일 (재확인)

통합 PRD 0장과 동일. 화면 설계 중 판단이 애매할 때마다 다시 참조할 것.

| 가져와도 되는 것 | 가져오면 안 되는 것 |
|---|---|
| 카테고리 브라우징, 실시간 컨센서스 %, 마감 카운트다운, 마이페이지 포지션 탭, 리더보드 | 오더북, 지분 매수/매도, 현금화, 배수의 유료 구매, "베팅/거래" 용어 사용 |

## 3. 타겟 유저 & 대표 시나리오

**페르소나 예시 — "지나", 22세, 필리핀 마닐라 거주**
특정 K팝 그룹의 해외 팬. 컴백 시즌마다 트위터에서 실시간 차트 순위를 직접 추적하며 소통방에 공유한다. 지금까지는 이 행동에 대한 보상이 "리트윗 좋아요" 정도였다.

**시나리오**: 지나는 트위터에서 공유된 SodaPick 링크를 타고 "이번 주 뮤직뱅크 1위는?" 캠페인에 들어온다. 이메일만 입력하고 옵션 하나를 고른다. 같은 소통방 친구 3명을 초대해서 예측 배수를 2배로 올린다. 며칠 뒤 정답 발표 알림을 받고, 자신이 맞혔다는 걸 확인한다. 클레임 화면에서 필리핀에서 쓸 수 있는 기프트카드를 고르고, 이메일로 받는다. 클레임 완료 화면에서 "이 선물처럼 당신도 해외 친구에게 선물해보세요" 배너를 보고 소다기프트 앱을 처음 설치한다.

이 시나리오 하나가 이 문서에서 정의하는 모든 화면·기능의 존재 이유다.

## 4. 상세 유저 플로우 (엣지케이스 포함)

1. **캠페인 진입** (피드 탐색 또는 초대 링크 직접 진입)
   - 엣지케이스: 이미 마감된 캠페인 링크로 진입 시 → "마감된 캠페인입니다" 상태 화면 + 현재 진행 중인 캠페인으로 유도
2. **예측 제출** (이메일 입력 → 옵션 선택 → 제출)
   - 엣지케이스: 동일 이메일로 같은 캠페인 재제출 시도 → "이미 참여하셨습니다" 안내, 기존 선택 표시
   - 엣지케이스: 제출 직후 캠페인이 마감된 경우 (동시성) → 서버에서 마감 시각 기준으로 최종 검증, 실패 시 명확한 사유 안내
3. **친구 초대** (초대 링크 공유 → 친구 가입 완료 시 배수 지급)
   - 엣지케이스: 이미 SodaPick에 참여 이력이 있는 유저가 초대 링크로 재유입 → 신규 유저로 카운트하지 않음, 초대자에게도 배수 미지급 (부정 획득 방지)
4. **결과 대기** (마감 → 판정 → 알림)
5. **당첨 확인 & 클레임**
   - 큐레이션된 선물 옵션 중 선택
   - 배송정보 입력 (이메일만 — `DeliveryMethod: EMAIL` 기준)
   - 엣지케이스: 클레임 시점에 선택한 선물이 품절(`DISCONTINUED`)인 경우 → 실시간 재고 재확인 후 대체 옵션 안내
6. **클레임 완료 & 발신 유도 CTA**
7. **(낙첨자 플로우)** 낙첨 시에도 "다음 캠페인 보러 가기" + 초대 링크 재노출로 이탈 방지

## 5. 화면별 상세 스펙

### 5.1 캠페인 피드 (홈)
- 구성: 카테고리 탭(전체/K팝/시상식/뷰티/e스포츠/드라마), 정렬(마감임박순/인기순), 캠페인 카드
- **카드에 반드시 들어가는 정보(우선순위 순)**:
  1. 스폰서사("OOO 제공")
  2. 옵션 목록과 옵션별 제출자 수 & 선택 비중(%) — 4지선다 전체를 카드에서 바로 보여준다(미니 % 바 + N명)
  3. 상품: **특정 선물(아이템형)** 또는 **디지털 재화 금액(포인트/캐시 등 금액형)** 중 하나로 캠페인을 구성할 수 있다. 카드에는 아이템형이면 "🎁 상품명", 금액형이면 "💰 O원 상당"으로 표시하며 상품 정보는 스폰서명과 함께 카드에서 가장 크게(제목급) 노출한다.
  4. 총 당첨 인원("총 N명 당첨") — 실제 정답자 수가 아니라 캠페인이 미리 정한 당첨자 정원
  5. 마감까지 남은 시간
- 썸네일 이미지는 카드마다 반드시 1장 포함한다(누락 시 카드 자체를 노출하지 않음).
- 상태: 로딩 스켈레톤, 빈 상태("진행 중인 캠페인이 없습니다")

### 5.2 캠페인 상세
- 구성: 상단 히어로 이미지 또는 동영상(캠페인 설명용, 필수 1개), 스폰서 배지(로고+이름), 상품 강조 영역(상품명 또는 금액, 총 당첨 인원), 질문, 4지선다 옵션(각 옵션에 실시간 선택 비율 % 바), **옵션별 선택 비중 추이 시계열 차트**(예측이 제출될 때마다 누적 비중이 어떻게 바뀌어왔는지 라인 차트로 표시, 옵션당 색상 구분 + 범례), 마감 카운트다운, 해결기준 설명("판정 기준: 멜론차트 O월 O일 O시 기준"), 상금 미리보기(큐레이션된 선물 옵션 목록 프리뷰)
- **필수 요소**: 스폰서와 상품(아이템 또는 금액)은 상세 화면에서도 빠짐없이 노출하며, 캠페인을 설명하는 이미지 또는 동영상이 최소 1개 있어야 한다(텍스트만으로 구성된 상세 화면 금지). 예측이 2건 이상 쌓이면 추이 차트가 노출된다(1건 이하일 때는 "추이를 표시할 만큼 데이터가 없다"는 빈 상태 문구).
- 인터랙션: 옵션 선택 시 즉시 확정이 아니라 "제출하기" 버튼으로 2단계 확인

### 5.3 예측 제출 확인
- 구성: 이메일 입력 필드(최초 1회), 선택한 옵션 요약, 제출 완료 후 초대 유도 배너로 자동 전환

### 5.4 초대 공유 시트
- 구성: 공유 링크, 배수 현황("2명 초대 완료 → 현재 2배"), 카카오톡/트위터/링크복사 공유 버튼

### 5.5 마이페이지
- 구성: 참여 중인 캠페인(진행중), 지난 예측 내역(적중/실패 표시), 당첨 내역

### 5.6 당첨 안내
- 결과 발표 시 이메일 + 인앱 알림. "축하합니다, 정답을 맞히셨어요" + 클레임 시작 버튼

### 5.7 클레임 — 선물 선택
- 구성: 큐레이션된 선물 옵션 카드(브랜드 로고, 금액/설명), 선택 시 실시간 재고 확인

### 5.8 클레임 — 배송정보 입력
- 구성: 수령 이메일 확인/수정, 메시지 카드 첨부(선택), 최종 확인

### 5.9 클레임 완료 & 발신 유도
- 구성: 완료 메시지, 예상 수령 안내, **"이 선물이 마음에 들었다면 당신도 보내보세요"** CTA 배너(소다기프트 발신 플로우로 연결) — 이 화면이 문서 전체에서 가장 중요한 화면

## 6. 기능 요구사항 (Acceptance Criteria)

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-1 | 캠페인 피드는 카테고리/정렬로 필터링 가능해야 한다 | 카테고리 선택 시 해당 카테고리 캠페인만 표시, 정렬 변경 시 즉시 재정렬 |
| FR-2 | 참가자는 이메일만으로 예측을 제출할 수 있어야 한다 | 비밀번호/결제수단 입력 필드가 어떤 플로우에도 존재하지 않음 |
| FR-3 | 동일 이메일은 동일 캠페인에 1회만 예측 가능하다 | 재제출 시도 시 기존 선택을 보여주고 재제출 차단 |
| FR-4 | 친구 초대는 가입 완료 시점에만 배수를 지급한다 | 링크 클릭만으로는 배수 미지급, 신규 이메일 가입 완료 시점에 지급 |
| FR-5 | 클레임 시 실시간 재고를 재확인한다 | `GET /v1/products/{id}/availability` 호출 결과가 `ON_SALE`이 아니면 대체 옵션 제시 |
| FR-6 | 리워드 발급은 중복 지급되지 않는다 | `external_reference_id`를 캠페인ID+라운드ID+참가자ID 조합(해시로 축약)으로 생성해 `POST /v1/orders` 호출 — 아래 8장 참고 |
| FR-7 | 클레임 완료 화면은 항상 발신 유도 CTA를 포함한다 | 예외 없이 모든 클레임 완료 시 CTA 노출 |
| FR-8 | 캠페인 카드는 스폰서·옵션별 제출자 수·선택 비중·상품(아이템 또는 금액)·총 당첨 인원·썸네일 이미지를 필수로 포함한다 | 하나라도 없으면 카드를 노출하지 않음, 스폰서/상품은 카드 내 시각적으로 가장 크게 표시 |
| FR-9 | 캠페인 상세는 스폰서·상품·설명 미디어(이미지 또는 동영상)를 필수로 포함한다 | 셋 중 하나라도 없으면 상세 화면 진입 불가, 미디어는 상세 화면 최상단에 노출 |
| FR-10 | 캠페인 상세는 옵션별 선택 비중의 시계열 추이를 보여준다 | 예측 제출 시점 기준 누적 비중을 시간순으로 재계산해 옵션별 라인으로 표시, 예측 2건 미만이면 빈 상태 문구로 대체 |

## 8. API 연동 상세 (소다기프트)

**클레임 시 선물 옵션 조회**
```
GET /v1/products?country_code={참가자국가}&page=0&size=10
```

**클레임 확정 시 주문 생성**
```bash
POST https://biz-sandbox-api.sodagift.com/v1/orders
Header: SODA-API-KEY
{
  "item": { "id": <선택한 product id>, "custom_amount": <가변금액 상품권일 때만> },
  "delivery": {
    "method": "EMAIL",
    "recipient": { "name": "<참가자 이름>", "email": "<참가자 이메일>" },
    "sender": { "name": "SodaPick" }
  },
  "message": "축하합니다! 예측에 성공하셨어요 🎉",
  "external_reference_id": "sodapick{campaign_id}{round_id}{participant_id}"
}
```
> 실호출로 확인함(2026-08-29, 고객사앱 쪽에서 검증): `external_reference_id`는 영숫자만 허용(하이픈·언더스코어 들어가면 400), `round_id`까지 넣어야 같은 캠페인 다른 라운드 당첨 시 값이 안 겹침. 가변금액 상품권(고정 `amount`가 없고 `min_amount`~`max_amount` 범위인 상품)은 `item.custom_amount`(스네이크케이스)를 꼭 같이 보내야 함 — camelCase나 top-level 필드로는 인식 안 됨. `lib/soda/client.ts`의 `createOrder`/`buildExternalReferenceId` 그대로 재사용 가능.

**클레임 페이지 상태 확인**
```
GET /v1/orders/{id}
```

## 9. 비기능 요구사항

- 모바일 퍼스트 반응형 (참가자 대부분이 SNS 공유 링크를 통해 모바일로 진입할 것으로 가정)
- 이메일 형식 검증 + 동일 이메일 중복 참여 방지 (FR-3)
- 초대 링크는 참가자별 고유 토큰 기반 (단순 캠페인 URL 공유와 구분되어야 배수 지급 로직이 정확히 동작함)
- 결제수단 입력 필드 자체를 코드베이스에 두지 않음 (설계 원칙 위반 방지를 물리적으로 강제)

## 11. MVP 컷라인 (해커톤 3분 데모 기준)

**반드시 있어야 함**: 캠페인 상세(5.2, 컨센서스 %·마감 카운트다운 포함) → 예측 제출(5.3) → 초대 공유(5.4) → 당첨 안내(5.6) → 클레임 전체(5.7~5.9)

**포함하기로 확정 (2단계 요소, 아래 순서로 빌드)**
1. 실시간 컨센서스 % — 구현 비용 대비 데모 임팩트가 가장 큼
2. 마감 카운트다운 — 사실상 5.2에 이미 포함, 거의 공짜
3. 카테고리 브라우징 — 캠페인 2~3개 하드코딩만으로도 "완성된 제품" 느낌 가능
4. 마이페이지 / 리더보드 — **주의**: 실제 참가 이력이 적으면 화면이 비어 보여 역효과. 넣을 경우 시연용 시드 데이터(가짜 참가자·랭킹)를 준비하고 심사위원에게 데모용임을 정직하게 밝힐 것. 시간 부족 시 가장 먼저 쳐낼 항목

**여전히 없어도 데모 가능**: 푸시 알림(이메일도 데모에선 생략, 관리자가 수동으로 "결과 발표" 트리거만 눌러도 됨)
